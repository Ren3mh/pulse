# Event format (v1)

Every event that enters pulse has this shape. The app sends it, the API
stores it, and every later phase (SQL models, queue, ClickHouse) reads it.
Changing it later is expensive, so changes bump `version`.

## Example

```json
{
  "version": 1,
  "event_id": "0b9a6f3e-4c1d-4e8a-9f2b-7d5c3a1e8b40",
  "event_name": "button_clicked",
  "distinct_id": "anon-5f2c9d",
  "occurred_at": "2026-10-18T19:42:07.123Z",
  "properties": {
    "button": "signup",
    "page": "/pricing"
  }
}
```

## Fields

| Field | Type | Required | Set by | Meaning |
| --- | --- | --- | --- | --- |
| `version` | integer | yes | client | Format version. Starts at 1. |
| `event_id` | UUID | yes | client | Unique per event. Sending the same event twice stores it once. |
| `event_name` | string | yes | client | What happened, as `object_verb` in past tense, snake_case: `page_viewed`, `button_clicked`. |
| `distinct_id` | string | yes | client | Who did it. An anonymous id until the user logs in, then their user id. |
| `occurred_at` | timestamp | yes | client | When it happened, ISO 8601 in UTC. |
| `properties` | object | no | client | Free-form details. Flat keys, snake_case. Defaults to `{}`. |
| `received_at` | timestamp | — | server | When the API got it. Never trusted from the client. |

## Rules

- The API rejects an event with a missing required field or an unknown `version`.
- `event_id` is generated by the client, not the server, so a retry after a
  network error does not create a duplicate.
- Both `occurred_at` and `received_at` are kept: client clocks can be wrong,
  and the gap between them shows delays (useful once there is a queue).
- `properties` never holds personal data such as names, emails or IP addresses.
