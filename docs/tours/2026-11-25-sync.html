Pulse sync tour

A tour of what issues #6 and #7 added: Pulse now copies the AX 2009 emulator and the Shopify dev store into Postgres every 15 minutes. Every number on this page comes from a real run on 25 November 2026 at 10:41 UTC.

The picture

Two sources, one database

Each source has its own worker inside Pulse.Api. Each worker reads everything from its source, then writes all of it to Postgres in a single step. Most tables are replaced on each run. Stock is appended, so its history builds up. The dashed boxes are what comes next.

Step through one run

What happens every 15 minutes

  1. A worker wakes up

    Each source has its own SyncWorker. It runs once at startup and then on a 15-minute timer. A failed run is logged and tried again on the next tick, so one bad run doesn't stop the worker.

    src/Pulse.Api/Sync/SyncWorker.cs:17 · catch at :25

  2. AX: open both databases and one transaction

    It creates the raw_ax tables if they're missing, then opens one Postgres transaction that covers the whole run.

    src/Pulse.Api/Ax/AxSync.cs:34 · schema in Ax/raw_ax.sql

  3. AX: replace six tables for company “pul”

    For each table it deletes that company's rows in raw_ax, then streams the AX rows over with a binary COPY. Other companies' rows are left alone. AX stores times in UTC without marking them as UTC, so the sync marks them before writing.

    AxSync.cs:39 delete · :60 COPY · :68 UTC

  4. AX: append a stock snapshot

    INVENTSUM only holds current stock, so it is added to raw_ax.stock_snapshots, stamped with this run's synced_at. This history is what the slow-stock analysis will read.

    AxSync.cs:47 · commit at :49

  5. Shopify: get a token if needed

    The client asks for a client-credentials token and remembers when it expires (expires_in: 86 399 s). It renews the token an hour before it runs out.

    src/Pulse.Api/Shopify/ShopifyClient.cs:20 · :52

  6. Shopify: read every page before writing

    The sync fetches all products, with their variants and stock levels, and all orders, following the cursor until the last page. The product query is priced at 478 of Shopify's 1000-point limit. If a product has more variants than one page holds, the run stops with an error instead of quietly skipping some.

    ShopifySync.cs:58 · :166 paging · :183 guard

  7. Shopify: write in one transaction

    Products and variants are replaced. Stock levels are appended to raw_shopify.stock_snapshots. Orders are updated in place, because without read_all_orders Shopify only returns the last 60 days, and replacing them would lose older orders. An order's lines are deleted and written again, because an edited order can lose lines.

    ShopifySync.cs:79 replace · :72 update in place · :145 lines · :162 commit

Run it yourself

Try it on your machine

Start the databases, then the API. Both syncs run right away. 
docker compose up -d
dotnet run --project src/Pulse.Api
Look at the snapshots growing, one set of rows per run: 
docker exec pulse-postgres-1 psql -U pulse -d pulse -c "SELECT synced_at, count(*) FROM raw_ax.stock_snapshots GROUP BY 1 ORDER BY 1;"
Compare Shopify and AX stock for the latest run: 
docker exec pulse-postgres-1 psql -U pulse -d pulse -c "
SELECT v.sku, s.available AS shopify, a.availphysical::int AS ax
FROM raw_shopify.variants v
JOIN raw_shopify.stock_snapshots s ON s.sku = v.sku
 AND s.synced_at = (SELECT max(synced_at) FROM raw_shopify.stock_snapshots)
JOIN raw_ax.stock_snapshots a ON a.itemid = v.sku AND a.inventdimid = 'DIM-LAGER'
 AND a.synced_at = (SELECT max(synced_at) FROM raw_ax.stock_snapshots)
ORDER BY 1;"
Run the tests (they start their own containers): 
dotnet test
What the 8 new tests prove

Tests

  • AxSyncTests.Copies_every_tableEvery table has the same row count in AX and raw_ax, and the line totals match.
  • AxSyncTests.Rerunning_appends_stock_and_replaces_the_restTwo runs: snapshots double, with two distinct synced_at values. Order lines don't duplicate.
  • AxSyncTests.Copies_only_the_configured_companyA second company in AX never reaches raw_ax.
  • ShopifySyncTests.Copies_the_catalogue_with_skus_and_barcodesAll 18 products. Every SKU's barcode matches the seed catalogue's GTIN.
  • ShopifySyncTests.Snapshots_stock_per_skuEach SKU's recorded stock matches the catalogue.
  • ShopifySyncTests.Reads_every_order_pageFollows the cursor to page two, and handles a guest order and a cancelled order.
  • ShopifySyncTests.Rerunning_appends_stock_and_replaces_the_restOrders are updated in place, not duplicated. Stock is appended.
  • ShopifyClientTests.Reuses_the_token_until_an_hour_before_it_expiresOne token for 22 h. A new one at 23 h, using a fake clock.
