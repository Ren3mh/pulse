The picture

From two raw copies to one model

The sync from the last tour copies each system as it is. The core views sit on top and are created when the API starts. core.products decides which AX item and which Shopify variant are the same product. The stock and order views use it to give Shopify rows the right SKU.

Step through it

How a SKU is decided

  1. AX gets barcodes

    The GTIN fallback needs a barcode on the AX side, and the emulator had none. Real AX 2009 keeps barcodes in INVENTITEMBARCODE, so the emulator, the seed tool and the AX sync now include it. The schema script creates the new table on its own, so an existing AX database gets it when ax-init runs again.

    ax/schema.sql:116 · AxSeeder.cs:63 · AxSync.cs:16

  2. The views are created at startup

    Before the workers start, the API creates the raw tables and recreates the core views, all in one transaction. If Postgres isn't running, it stops with a message saying so, rather than running with no views.

    src/Pulse.Api/Core/Schema.cs · Program.cs:39

  3. Match on SKU first

    An AX item and a Shopify variant with the same SKU are one product. This covers all 30 seeded SKUs today.

    src/Pulse.Api/Core/core.sql:32

  4. Then on GTIN

    If an AX item has no Shopify variant with its SKU, and that variant's SKU isn't used by another AX item, the two are matched on barcode. The row keeps the AX item number as its SKU and records matched_on = 'gtin'.

    core.sql:36

  5. Anything left gets its own row

    An item found in only one system still appears, with in_ax or in_shopify false. That's how a product missing from the webshop will show up.

    core.sql:46 · columns from :59

  6. Stock and order lines borrow the matched SKU

    Shopify stock and order lines are joined to core.products by Shopify id. A variant matched by GTIN is then counted as its AX item, even though its own SKU is different.

    core.sql:85 · :149

  7. Current stock is the latest snapshot

    core.stock keeps only each source's newest snapshot, while core.stock_snapshots keeps every run for the slow-stock analysis. Both sources stay side by side: which one to trust is a question for the tools that read them.

    core.sql:94

What the data already shows

The seed tool built three customers who drift away. Each one shows up with a short query on core.orders, core.order_lines and core.products, with no AX table names involved. This is the groundwork for the B2B churn analysis.

Run it yourself

Try it on your machine

If your AX database is from before this change, add the barcode table and reseed AX: 
docker compose run --rm ax-init
dotnet run --project src/Pulse.Seed -- ax
Start the API. It creates the views, then syncs: 
dotnet run --project src/Pulse.Api
How many Oslo sofas are free in the warehouse? 
docker exec pulse-postgres-1 psql -U pulse -d pulse -c "SELECT sku, source, location, available FROM core.stock WHERE sku LIKE 'OSLO%' ORDER BY 1, 2, 3;"
One customer's orders, with the customer name from AX: 
docker exec pulse-postgres-1 psql -U pulse -d pulse -c "SELECT order_number, created_at::date, status, total FROM core.orders WHERE customer_id = '10004' ORDER BY 2;"
What the 11 new tests prove

Tests

They share one lab: AX seeded in SQL Server, both syncs run (Shopify from its recordings), and the views created. Tests that change rows do it in a transaction they roll back.

  • Every_catalogue_sku_is_one_product_found_in_both_systemsAll 30 SKUs matched on SKU, each with the catalogue's GTIN.
  • Ax_list_price_and_shopify_price_agreeThe AX list price equals the Shopify price. B2B-only items are drafts.
  • Falls_back_to_gtin_when_the_skus_differA renamed Shopify SKU is still matched to the AX item by barcode, stock included.
  • An_item_in_one_system_only_still_gets_a_rowA web-only variant and an AX-only item each get their own row.
  • Both_systems_count_the_same_warehouse_stockOn-hand stock matches per SKU between AX's warehouse and Shopify.
  • Ax_available_stock_is_on_hand_minus_reservedTrue on every row, and some stock really is reserved.
  • Stock_shows_only_the_latest_snapshotWith two snapshots in history, current stock is the newer one.
  • Orders_come_from_both_systemsAll 345 AX orders and 2 Shopify orders, with statuses and customer names.
  • Ax_order_totals_are_the_sum_of_their_linesHolds for every AX order.
  • Shopify_order_lines_get_the_matched_skuA line keeps the AX SKU when its variant was matched by GTIN.
  • The_churned_customer_stops_orderingØstby Kommune's last order is more than three months old.
Still open

Decisions for you

Now

Commit and push this to phase-1-lab. Then #9, the MCP server.

For #9

When asked “how many are in stock?”, should Claude answer with AX's free warehouse stock (17 Oslo sofas) and mention Shopify only when they differ?

Totals

An AX order's total is the sum of its lines. A Shopify order's total includes shipping and tax. Fine while Shopify has no orders, but worth settling before comparing revenue.

Real AX

The views assume one AX company and that a SKU is the AX item number. The schema extract (#3) will show whether that holds.
